# Rectangle Approximation

## Problem

You are given $N$ axis-aligned rectangles with integer coordinates, and a parameter $K$. Output exactly $K$ axis-aligned rectangles (with integer coordinates) that best approximate the union of the original $N$ rectangles.

Let $A$ denote the union of the $N$ input rectangles and $B$ denote the union of your $K$ output rectangles. The score for a test case is:

$$\text{score} = \max\!\left(0,\ 1 - \frac{|A \triangle B|}{|A|}\right)$$

where $|A \triangle B| = |A| + |B| - 2\,|A \cap B|$ is the area of the symmetric difference and $|A|$ is the area of $A$ (measured in unit squares). A higher score is better; a perfect score of $1$ is achieved when $B = A$.

This is an optimization problem: any feasible output is accepted and scored.

---

## Input

```
N K
x1_1 y1_1 x2_1 y2_1
x1_2 y1_2 x2_2 y2_2
...
x1_N y1_N x2_N y2_N
```

* $1 \leq K \leq N \leq 1000$
* Each rectangle is given as $(x_1,\ y_1,\ x_2,\ y_2)$ with $x_1 < x_2$ and $y_1 < y_2$
* $-1000 \leq x_1 < x_2 \leq 1000$, $-1000 \leq y_1 < y_2 \leq 1000$, all integers
* **The $N$ input rectangles may overlap each other.**

---

## Output

Output exactly $K$ lines, each describing one axis-aligned rectangle:

```
x1_1 y1_1 x2_1 y2_1
x1_2 y1_2 x2_2 y2_2
...
x1_K y1_K x2_K y2_K
```

Each output rectangle must satisfy:

* $-1000 \leq x_1 < x_2 \leq 1000$, all integers
* $-1000 \leq y_1 < y_2 \leq 1000$, all integers

The $K$ output rectangles **may overlap each other**.

## Feasibility Requirements

Your output is **feasible** if and only if it contains exactly $K$ valid rectangles as described above. An infeasible output receives a score of **0** on that test.

---

## Scoring

For a feasible output, the per-test score is:

$$\text{score} = \max\!\left(0,\ 1 - \frac{|A| + |B| - 2|A \cap B|}{|A|}\right)$$

where areas are measured in unit squares. The overall judge score is the **average** of per-test scores across all test cases.

---

## Test Generation

There are **30 judge test cases**. Each test is generated using an organic clumping process:

**Rectangle generation** — Rectangles are built one at a time:
* The first rectangle, and each subsequent rectangle with 30% probability, is placed at a fresh random position and size.
* Otherwise (70% probability), an existing rectangle is chosen at random and mutated: its center is shifted by Gaussian noise proportional to its own dimensions, and its size is scaled by a log-normal factor, then clamped to the coordinate bounds.
* All rectangles are shuffled before output so the generation order is not visible.

**Parameter ranges:**
* $N$ is drawn uniformly from $[1, 1000]$
* Coordinates are integers in $[-1000, 1000]^2$

**Choosing $K$** — Rather than picking $K$ uniformly, $K$ is tied to the structural complexity of the generated rectangles:
1. The overlapping-cluster count $C$ is computed: two rectangles are in the same cluster if their interiors intersect (directly or transitively).
2. $K$ is drawn uniformly from $\bigl[C,\ \min(N,\ C + \max(1, \lfloor N/5 \rfloor))\bigr]$.

This means $K \geq C$, so you always have at least enough rectangles to represent every disjoint cluster, but $K$ is generally much smaller than $N$, requiring non-trivial merging of overlapping rectangles within each cluster.

* Time limit: 5 seconds
* Memory limit: 512 MB
